# Карточки Ozon и AliExpress

Worker раскрывает короткую ссылку, извлекает артикул и читает цену, фотографии и другие данные из метаданных открытой страницы товара. Ключи API маркетплейсов для этого не нужны.

Если магазин показывает проверку или ограничивает доступ к странице, сохранится карточка по ссылке и артикулу. Недостающие данные можно внести через «Дополнить». Для AliExpress можно вставить весь текст из меню «Поделиться», чтобы использовать название и цену из него.

Для проверки отправьте ссылку в поле `url` запроса `POST /api/parse`. При наличии текста из «Поделиться» передайте его в поле `shareText`. Ответ содержит `product`. Если короткая ссылка не раскрывается, используйте полный адрес страницы товара.

## Вход в приложение

Добавьте секрет `APP_ACCESS` в настройках Cloudflare Worker или через `wrangler secret put APP_ACCESS`. Значение — объект JSON с полем `password` и случайным 64-символьным шестнадцатеричным ключом `signingKey`. Ключ можно сгенерировать командой `node -p "require('node:crypto').randomBytes(32).toString('hex')"`. Для локальной разработки задайте тот же секрет в файле `worker/.dev.vars`.

Проверка здоровья `GET /api/health` доступна до входа. Для доступа к карточкам и подборкам получите токен запросом `POST /api/auth/login` с полем `password` и передавайте его в заголовке `Authorization: Bearer <token>`. При смене пароля или ключа устройства запросят пароль снова.

## Уведомления

Сервер записывает события в таблицу `events`: лайк (`like`), совпадение, когда товар нравится обоим (`match`), новый товар (`add`) и новую подборку (`board`). Кто действует, сайт сообщает заголовком `X-Actor: m|f`. События хранятся 14 дней. Их отдаёт `GET /api/events?since=<мс>` в виде `{ now, events }`: новые сверху, не больше 50.

Приложение для Android само опрашивает этот адрес в фоне, Firebase не нужен. Для браузеров работает Web Push. `GET /api/push/key` отдаёт открытый ключ VAPID. `POST /api/push/subscribe` принимает поля `subscription`, `role` и `settings`, а `POST /api/push/unsubscribe` — поле `endpoint`. Пару ключей VAPID сервер создаёт сам при первом обращении и хранит в D1 (таблица `config`), поэтому настраивать ничего не нужно. Свои ключи можно задать секретами `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` в формате `npx web-push generate-vapid-keys`. После смены ключей сайт сам переподпишет браузер при следующем запуске.

Для локальной проверки push запустите `wrangler dev --var PUSH_DEV:1`. С этой переменной сервер принимает подписки с адресом `http://localhost:…`. Без неё принимаются только адреса push-сервисов браузеров.
